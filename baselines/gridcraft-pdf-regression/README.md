# GridCraft PDF regression (phase 1 of the refactor)

What it is: the test that proved that the refactor of GridCraft's `print.rs` (phase 1, a single file) does not change the PDF output. It compares PDFs generated by the original code's binary (the "goldens") against those generated by the refactored copy, in three layers. Final result: 325 of 325 cases PASS, 306 of 306 PDFs byte-for-byte identical, 0 differing pixels.

Date: 2026-10-19. It serves any future GridCraft update: if the upstream PDF changes on purpose, the goldens must be regenerated with the new original commit.

## Versions

| Item | Value |
|---|---|
| Original GridCraft commit (goldens) | `66ce6be4743f4227047f76f56815520f824e6d81`, unmodified tree (see `ORIGIN.txt`) |
| Original binary | `gridcraft-cli` built with `cargo build -p gridcraft-cli` (the repository's own optimized dev profile, with debuginfo, 221 MB), sha256 `8d22cb4dbcef502d6d204c9d91b1a39d6b593e974e00b0ffd99032ab36eb3c3c` |
| Rust | 1.97.0 |
| Tools | `cmp`, `qpdf` 11.9.0 (layer B), `pdftoppm` 24.02.0 and ImageMagick `compare` 6.9.12 (layer C) |

## The three layers

- A, bytes: `cmp` between the golden PDF and the new one. No normalization (the writer emits no date, `/ID` or UUID, checked on the 306 PDFs). The script's normalization list is empty on purpose.
- B, content streams: only runs when A fails. `qpdf --qdf --object-streams=disable` on both PDFs and a diff of the operations.
- C, pixels: `pdftoppm` at 50 dpi, page by page, `compare -metric AE`. Expected: 0.
- In addition, the output text and the exit code of every case must be equal, including the 19 cases without a PDF (errors).

## Coverage

64 input spreadsheets: the 16 in `../../corpus/xlsx/regressao-amostras/` (prefix `s-`) plus the 48 .xlsx in `../../corpus/xlsx/` (prefix `c-`). Each in 5 variants: default `exportPdf` (`.d`), `fitToPage` (`.fit`), `range` B2:F30 (`.rng`), `sheets:"all"` (`.all`) and `file.print` (`.prn`). Plus 5 error cases with invalid parameters (`err.*`). Total: 64 x 5 + 5 = 325 cases, 306 of them with a PDF.

## Contents

| File | What it is |
|---|---|
| `regress-pdf.sh` | the script (bash). `golden` generates the goldens with the original binary, `check` (the default) rebuilds the copy, regenerates and compares. Exits non-zero if there is any FAIL |
| `tabela-final-325-de-325.txt` | per-case table of the final run (the accepted result) |
| `tabela-teste-de-sanidade-do-detector.txt` | sanity test: a defect was injected (shifting the `x` of every `FillRect` by 1 unit) and the detector reported FAIL in 99 cases (226 of 325 PASS), with all three layers reporting, and after reverting it went back to 325 of 325 |
| `SHA256SUMS` | sha256 of the 306 golden PDFs (145 distinct contents, because equal variants generate equal PDFs) |
| `ORIGIN.txt` | original commit, clean-tree indicator (0) and sha256 of the original binary |
| `fase1-print-rs.patch` | the phase 1 patch: only `crates/engine/src/cmd/print.rs`, +118 and -14 lines (`enum Op`, `struct Rec`, `fn replay`) |

The golden PDFs (19 MB, 306 files) and the original binary (221 MB) were not copied. The hashes are enough to prove identity.

## How to regenerate the goldens and repeat the test

1. Get GridCraft at commit `66ce6be4743f4227047f76f56815520f824e6d81` (`scripts/fetch-upstream.sh` does this in `third_party/gridcraft`, but with the patch already applied: use a clean clone for the original) and build the original binary: `cargo build -p gridcraft-cli`. Keep a copy of the binary outside `target`, because the patched binary has the same name.
2. Copy this folder to a working directory outside the repository (the script writes `golden-pdf/` and `new-pdf/` next to itself, and the PDFs add up to tens of MB).
3. Set the variables and generate the goldens: `SAMPLES=<repo>/corpus/xlsx/regressao-amostras CORPUS=<repo>/corpus/xlsx ORIG_BIN=<original binary> ./regress-pdf.sh golden`.
4. Check against the `SHA256SUMS` here: `cd golden-pdf/pdf && sha256sum -c <repo>/baselines/gridcraft-pdf-regression/SHA256SUMS`. All must be OK if the commit and Rust are the same.
5. Apply the patch (or the new version) to a clone, and run `COPY=<patched clone> SAMPLES=... CORPUS=... ORIG_BIN=... ./regress-pdf.sh check`. Requires `qpdf`, `pdftoppm` and `compare`.

The script also accepts `NO_BUILD=1`, `NEW_BIN`, `CARGO_TARGET_DIR` and `DPI`. Without `NEW_BIN`, it looks for the binary at `$CARGO_TARGET_DIR/debug/gridcraft-cli`.

The generator of the 16 sample spreadsheets was an unversioned Python script. The generated spreadsheets are in `../../corpus/xlsx/regressao-amostras/`, and `../../docs/TESTS.md` describes the coverage.
